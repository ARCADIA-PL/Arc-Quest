# ArcQ 图鉴任务玩法重审与统一调查方案

日期：2026-10-03

状态：**本轮实现与验收完成。** Forge 1.20.1 与 NeoForge 1.21.1 已对齐统一调查、规则冻结、成果、奖励、事件、编辑器和客户端交互；两端服务端回归与构建、有／无 JEI 四轮原生 GUI 审计及最后的单测／构建复验全部通过。实际接口以 [统一调查使用说明](compendium-unified-quest-usage.md) 为准；[验收记录](compendium-quest-verification.md) 列出实际证据及无世界 GUI、联网存档、JEI 配方屏和多人压测的验证边界。以下保留设计要求，不将要求本身视为测试证据。

适用：Forge 1.20.1、NeoForge 1.21.1，两端采用相同玩法规则。保留 `QuestMode.COLLECTION`、图鉴任务类别、任务面板内嵌目录、半透明次级档案和按条目调查追踪。

## 1. 结论与玩法定位

图鉴任务应当是“通过一份调查委托取得资料、留下档案”，而不是对同一对象同时做发现、永久研究和本轮调查三份近似任务。

推荐保留两个玩家行为：**发现对象、完成当前调查。** 永久档案是这两个行为留下的结果，不再有独立的 Research 目标组。

| 概念 | 新职责 | 是否独立累计调查进度 |
| --- | --- | --- |
| Entry 条目 | 定义对象、发现方式、资料和可取得的档案成果 | 只检测发现；不维护研究计数 |
| Discover 发现 | 记录玩家首次符合条件的接触 | 通常是一次事实，永久一次 |
| Binding 调查 | 引用当前 Phase 的 Objectives，说明本次要做什么 | **唯一调查进度来源** |
| Outcome 档案成果 | 指定调查完成后记下“解剖记录”“燃料试验”等事实 | 不计数，不自行监听行为 |
| Quest / Phase | 组织调查章节、并行、配额和交付流程 | 使用正常任务生命周期 |

最小配置只有 Entry 的发现规则和 Binding 的目标。普通调查不必配置 Outcome；需要长期解锁资料或首次成果奖励时才添加它。不能为了取代 Research，再建立一套与 Binding 同时计数的“成果任务”。

调查内容也应有不同用途，不能把所有条目改成“再击杀几只”：

| 调查类型 | 推荐玩法 | 配置重点 |
| --- | --- | --- |
| 入门收录 | 找到或首次接触对象 | 接受已有发现，不为纯记录验收反复支付 |
| 专题调查 | 少量实际行动＋有意义的样本提交 | 完成一份调查，取得一份实用档案 |
| 材料试验 | 制作、受支持的冶炼或样本交付 | 准确说明来源和消耗，资料解释材料用途 |
| 地点调查 | 到达配置地点并完成当地的明确行动 | 地点验证用真实条件，不把附近扫描当默认功能 |
| 重复外勤 | 本轮行为，候选任选，回报结束 | 真实投入、冷却和报酬，已有资料保留 |

每项默认控制在 1–3 个清晰要求，避免同种击杀层层加量。章节数量与门槛根据整合包的生成频率和资源稀缺度调整；新 Demo 演示规则，不充当所有整合包的平衡数值。图片和正文应解释这次调查学到了什么，不能把解锁一张装饰图当作默认的全部成长价值。

## 2. 重审时的玩法问题与源码依据

| 重审时的现状 | 玩家感受到的问题 | 新方案 |
| --- | --- | --- |
| 僵尸 Demo：发现击杀 1、研究击杀 5、本轮击杀 3＋提交腐肉 2 | 同一件事重复做，难以理解何时“完成” | 删除永久击杀 5；本次调查完成直接取得解剖记录 |
| 默认公开 Entry 可在未发现时浏览；图文有独立 reveal 规则 | “已经能看档案”被误认为“已经发现” | 公开基础资料与个人发现事实分别表达 |
| `researchComplete()` 对空研究集合使用 `allMatch` | 牛、骨头发现后也可能被算作研究完成 | 无显式成果就只有“已收录”，不自动生成深入调查 |
| Entry 的 `bindingReward` 应用于引用它的各个 Binding | 简单发现、采集和提交都可能发相同报酬 | 本次报酬配置在具体 Binding |
| 条目未达成奖励的定义被服务端遮蔽 | 铁粒等奖励像不存在，无法知道条件 | 公开奖励可以预告；神秘奖励保留遮蔽 |
| 拾取与背包正向变化驱动 COLLECT | 丢出再捡回、容器往返都可能刷累计 | 区分持有、真实来源和消耗提交 |
| `NEW_DISCOVERIES` 只认可接取时尚未发现的条目 | 熟悉所有候选的玩家无法完成“新发现” | 限于探索任务；重复调查默认要求本轮行为 |
| 并行 Demo 使用长期全局 flags 汇合 | 新一轮可能受上一轮或 reset 前的 flags 影响 | 汇合只读取当前 run 的阶段完成事实 |
| 一次合成先派发 CRAFT，再派发 COLLECT | 同一产物可能推进新激活的后续阶段 | 按一次来源事件批量更新，再统一推进阶段 |
| 追踪点击受 0.2 秒 dwell 就绪条件限制 | 快速点击没有反应 | 延迟只控制文案动画，点击立即有效 |
| 单任务 reset 保留防回填标记；resetall 清全部记录 | resetall 后登录可能重新从旧背包建立发现 | 统一明确重置与登录导入规则 |

主要依据：

- `quest/registry/CollectionFieldDemos.java`：现有三个 Demo 和重复目标。
- `quest/logic/profile/collection/CollectionProgressProjector.java`：研究、记录要求、distinct 计数和 reveal 投影。
- `quest/logic/CollectionEntryRewardService.java`：奖励归属、下发权限和领取凭证。
- `quest/tracking/QuestEventManager.java`：拾取、背包 diff、合成和阶段事件顺序。
- `quest/logic/CollectionRecordService.java`：独立研究监听、登录库存发现和记录资格。
- `questplayer/ArcQuestPlayer.java`、`quest/data/CollectionRecordState.java`：reset / resetall。
- `client/hud/quest/journal/detail/JournalDetailCollection.java`：详情中的三组进度与 dwell 点击。

本节保留重审时的问题与依据，表中旧行为不代表当前实现。新版单任务 reset / resetall 已统一重置世代与关联知识、奖励及库存导入规则，两端真实服务端回归已通过；具体证据见验收记录。

## 3. 发现、公开资料和档案成果

### 3.1 发现要表达真实接触

发现不一定要求击杀。牛可用互动，材料可用首次获得，敌对生物可用作者明确指定的击败事件。推荐数量为 1；把发现配置成大量重复操作，会再次把它做成调查。

发现规则可以在未接取相关 Quest 时生效，永久档案成果只由有资格的当前调查产生。此前击杀很多僵尸可以代表“已发现”，不会凭空补足后来接取的击杀目标。

不新增默认全世界生物扫描。现有 INTERACT 代表交互事件，不能直接宣传为看见、成功挤奶或完成繁殖。若以后增加观察、挤奶等能力，必须有准确的服务端事件适配和对应文案。

首次接触发生在当前调查激活时，同一个真实事件可以同时记下发现并推进这份调查一次；玩家不需要为“先发现再调查”多做一次动作。

### 3.2 三种资料公开策略

| 策略 | 未发现时 | 发现后 | 指定调查后 |
| --- | --- | --- | --- |
| 基础公开，推荐默认 | 名称、头像、短介绍、发现线索、公开目标；标“尚未发现” | 实用基础资料、相关物品、发现图文 | 对应深入资料和成果印记 |
| 线索占位 | 匿名条目与作者提供的公开线索 | 显示真实身份和基础资料 | 显示深入资料 |
| 完全隐藏 | 不显示身份或图标；任务需有足够公开线索和可完成候选 | 按权限显示 | 按权限显示 |

单纯能打开基础档案不表示已发现，不能用“已解锁”概括全部状态。默认文案采用“尚未发现 / 已收录”，深入资料使用具体成果名。

发现后应提供有用信息，例如掉落用途、行动特点或材料来源。作者仍可配置只有图片或纯百科内容，但 Demo 不应只靠多一张图片表现发现价值。发现门槛与资料内容都由作者决定，不强迫每个条目拥有三个解锁层。

### 3.3 `content` 的清晰定位

`content` 仍是正文、图片、说明等资料块，不是计数器，也不会自动完成目标。新 reveal 条件只保留：公开、发现后、取得指定成果后。

锁定块显示获准的标题和解锁条件，例如“解剖笔记：完成林地调查中的僵尸调查后公开”。隐藏块不下发正文、图片或秘密条件。

默认在整个 Binding 完成后解锁深入资料。若确实需要途中解锁，只能显式绑定到现有 Objective 的真实达成事件，并把结果记为资料事实；不另写一份相同调查目标。

## 4. 唯一调查目标与永久成果资格

### 4.1 Binding 承担本次行为

Binding 继续引用同一 Phase 的 Objectives。数量、目标物品、Tag、提交消耗和事件源只写一次；Entry、档案和追踪器读取这份定义及其进度。

默认本轮行为从对应 Phase 激活后起算；已有事实要求可明确写成“已发现”或“已有某成果”。二者在文案和资格上区分。

普通 Binding 完成并不自动获得永久调查成果。以下三个 Binding 必须有不同含义：

| Binding | 完成后 |
| --- | --- |
| 已发现僵尸 | 本手册的收录要求达成 |
| 本轮击败僵尸 1 次 | 本委托的行动要求达成 |
| 击败 3 次＋提交 2 份腐肉，显式产出 `anatomy` | 本次调查达成，并首次登记解剖记录 |

不能让一个 `.discovered()` Binding 因为引用僵尸 Entry，就自动解锁全部资料和首次调查奖励。

### 4.2 成果只有身份、资料和取得事实

建议成果使用 `entryId + outcomeId`，例如 `arc_quest:codex/zombie + anatomy`。记录取得时间、来源任务和必要版本，不存第二套累计击杀或获得数量。

成果定义可以包含名称、解锁图文和首次奖励；取得条件是显式指定的 Binding 完成。默认只认可整个 Binding 的必需要求达成，不把完成任意一项可选目标当作整个调查完成。

每个成果指定一个标准调查来源。确需多个任务产出同一成果时，作者明确登记等价来源；注册校验检查条目、目标和权限，不能通过“引用同一 Entry”自动认为等价。成果已取得后再次完成等价调查只产生本次报酬。

成果调查必须明确要求已经发现，或包含能够同时建立发现的有效行为；不能出现“深入档案已取得、主体仍未发现”的默认矛盾。调查提交了别的材料，并不自动证明玩家接触过这个生物。

成果只在有效调查的实际完成边沿登记，保存来源完成凭证和 Entry 的重置世代。登录、刷新、旧归档和已完成锁存不能重复授予；管理员 reset 之后也不能用重置之前的完成记录重建知识或首次奖。

如果高级成果要求初级成果，写成当前调查的显式前置条件，并给出可操作的来源提示。不允许自循环或只有互相等待的来源。

### 4.3 认可旧成果是显式任务规则

一次性的入门手册可以直接认可“已收录”；一次性的专题手册可以显式认可已有 `anatomy`。它们是记录验收，不假装玩家重新执行过行为。

可重复委托默认要求本轮行动。永久事实不能无条件转换成本轮行动进度，重复任务也不能仅凭已有成果反复领奖。若作者配置“已有记录即可完成”，其经济奖励必须为首次一次或有明确、可验证的本轮成本。

## 5. 奖励归属、领取和经济循环

| 奖励 | 定义位置 | 领取身份与次数 |
| --- | --- | --- |
| 首次发现，默认可不配置 | Entry | 玩家＋Entry＋rewardId 一次 |
| 首次取得档案成果 | Outcome | 玩家＋Entry＋outcomeId＋rewardId 一次 |
| 本次调查报酬 | 实际 Binding | 玩家＋Quest＋run＋phase＋binding＋rewardId 一次 |
| 分类、阶段、整本手册 | 对应任务层级 | 按各自稳定节点与任务生命周期 |

同一份调查可同时获得首次成果奖励和本次报酬：首次成果奖鼓励新知识，本次报酬支付实际投入，不再要求另一套 Research 行为。发现奖是可选项；常见材料 Demo 不需要每捡一种物品都发一次奖励。

分类、阶段、章节和条目奖励都可保留，但默认范例不叠满所有层级。底部继续使用“调查奖励 / 章节奖励”等现有切换形式，不追加一排排重复条带。

### 5.1 可见性与资格分开

公开调查默认可提前预览奖励物品、数量和精确条件。成果奖励写“首次取得解剖记录”，本轮报酬写“完成本次僵尸调查”。未达成时显示条件；可领时显示醒目按钮和红点；领取后原位显示“已领取”。

作者声明的隐藏条目和神秘奖励仍由服务端控制遮蔽。预览包只包含获准的展示信息，不下发奖励执行指令。预览不等于领取资格，也不能绕过隐藏物品的 JEI 授权。

奖励的次数、解锁和领取由服务器确定。旧轮欠奖清楚标“上次调查”，按原 run 领取；即使任务已完成、放弃或已接新轮，也提供欠奖入口。

### 5.2 重复委托的放弃重接防刷

对于允许重复接取的委托，不能只检查“本轮一次”就认为安全：领取简单 Binding 报酬后放弃、立即重接，也会形成循环。

明确可重复委托允许按新 run 再领奖，但要有真实投入；冷却从接取或报酬资格产生时计入，不能只在整任务完成时设置、被放弃绕过。需要履约才支付的委托，显式把本轮报酬解锁时机设为阶段或任务回报；UI 提前写明。

真实生命周期验证修正了初稿中的假设：ArcQ 的非重复任务放弃后进入失败终态，生产接取服务返回 `ALREADY_COMPLETED_NOT_REPEATABLE`，不存在正常“取消重接”的免费循环。因此实现不对合法的一次性 Binding、Phase 或里程碑报酬强加重复成本要求；防刷与冷却校验只针对可重复任务。正常 reset 是管理员工具，可明确重新授予资格；不撤回已发到背包的物品。

### 5.3 领取表现和可靠性

领取不弹 Toast。仅更新奖励行、红点和可选的轻提示音；不重新构建详情、不改变滚动位置、当前页签或动画阶段。按钮宽度和条带高度固定。

服务端重复点击和重复请求必须幂等；内置物品奖励需处理满背包和待交付恢复。重审前的“先标记内存凭证，再执行奖励，最后保存”不能直接等同于跨崩溃事务。新版已对内置奖励建立持久授权、待交付日志、真实玩家文件回执与恢复协议；任意指令、外部经济插件或自定义回调需单独声明失败重试能力，不承诺通用严格一次发放。

## 6. COLLECT、Tag 与行为质量

### 6.1 不能把防重复事件等同于防重复物品

现有 COLLECT 统计拾取与背包数量的正向变化。消除“同一拾取事件又被 diff 算一次”只能修重复派发，不能阻止物品离开背包后再次进入。

推荐按作者真正的目的选择目标：

| 玩家目的 | 推荐语义 | 防刷与边界 |
| --- | --- | --- |
| 第一次见到材料 | Discover 首次获得 | 幂等，只记录一次 |
| 备齐 5 个材料 | 明确的持有目标，读取当前库存 | 丢出再捡回不会积成 5 个；已有库存是否认可明确展示 |
| 提交 5 份样本 | OFFER / DELIVER，实际扣除 | 不累计未消耗的循环搬运；新 Demo 优先采用 |
| 本轮真实制作或采集 5 个 | 来源明确的真实事件 | 只统计有适配的来源，不把容器转移视为新产出 |
| 累计搬入任意来源物品 | 保留旧 COLLECT 兼容语义 | 明示边界，不作为可重复经济奖励的推荐目标 |

持有目标在 Binding 未达成前反映当前库存；完成锁存代表已经证明该次条件，不代表已消耗材料。可重复报酬不能只靠持有同一批材料反复完成。若要求交付，就使用实际提交，避免“持有后又提交导致计数冲突”的两份相同样本目标。

持有是实时条件，不是本轮获得计数：明确允许旧库存的持有目标，接取时就可能达成。管理员 reset 不撤走背包物品，所以不能同时保证这类条件仍真实又始终显示零。为了满足 reset 后重新 give 从零的调查体验，新 Demo 的累计与奖励调查采用真实新行动或提交，不采用自动认可旧库存的持有条件；实时持有仅作为作者明确选择的准备条件，并在配置预览中说明。

旧 COLLECT 不静默改成持有，否则会改变已经发布的任务与存档。新配置显式选择语义，编辑器解释区别，并对高奖励、可重复且容易循环的配置给出诊断。

来源追踪只对支持的制作、掉落、交易或其他适配事件保证语义。给所有 ItemStack 添加全局 UUID 会牵涉拆分、合并、合成、容器和模组兼容；不是首版必须项。仅过滤玩家 Toss 也不能解决玩家互扔或容器循环，不能宣称全面防刷。

### 6.2 Tag 数量与种类

“任意原木共 8 个”与“调查 3 种原木”是不同玩法。前者聚合匹配物品数量，后者需要独立 Entry / 不同成员记录及明确的种类完成规则。Tag 图标轮换只表示可用候选，不表示需要逐个收集全部候选。

悬停固定当前轮换物品，Tooltip 复用奖励栏，JEI 左键查询该物品配方、右键用途；用户离开后恢复轮换。显示 Tag 友好名称及“任选”的条件，不加入快捷键说明。

候选集合和完成门槛随当前 run 冻结；热重载或 Tag 改动不能使旧目标无声改变、撤回已取得成果。新 run 使用新候选；不可完成的配置需要报告具体原因。

### 6.3 其他重复行为也要审核

INTERACT 多次右键同一只牛并不等于挤奶调查；CRAFT 制作可逆配方也可能成为无成本循环。高奖励委托应采用成功事件、不同样本要求、消耗交付或履约条件。系统不要把普通互动自动升级为成功使用某项生物能力。

## 7. 阶段、QUOTA、并行与跨任务

- ALL 写“完成全部 6 项调查”；QUOTA 写“6 项候选，任选 3 项”。不把击杀数、提交数或 Tag 成员数加成“条目数”。
- 同一 Entry 在同表出现多个调查，默认合并到一个条目卡内并分别显示调查名。若按不同 Entry 计配额，必须明确该条目下是全部达成还是任一达成，不能让 distinct 的隐式 AND 隐藏在内部。
- 同一个真实来源事件先冻结活跃任务与阶段，规范化 CRAFT、获得等子事实，更新各目标，然后统一结算 Binding、成果和阶段。新激活阶段不再次消费这次来源事件。
- 自动奖励在本次结算之后交付，不递归推进本次调查。奖励物品不是制作或采集的来源证明；允许普通获得计数的旧规则仍按其兼容语义处理，不能把赠送物品伪装成新的生产行为。
- QUOTA 达标时，先处理本事件产生的全部有效完成，再冻结本轮结算结果与奖励资格。默认停止余下候选的本轮计数；仍可浏览、收藏，长期发现继续有效。任务文案提前说明“任选，达标结束本轮调查”，不让玩家在等待回报时偷偷刷余下报酬。
- 可选调查不计必需分母；若只在结算前有效，明确标注。未完成可选项不阻止回报。
- 并行调查分别展示生物、材料等表的要求；合流条件读取同一 `runId` 的真实阶段完成事实，禁用长期全局 flags 作为本次汇合依据。
- 两个活跃任务可以各自认可同一次非消耗行动，这是独立委托的明确默认。一次样本提交只从一个绑定实际扣除，不能被多份任务当成分别交付。
- 重复引用同一个消耗 Objective 作为多份调查的报酬来源需要显式校验，避免“一份提交被包装为多份支付”。作者有意设计共同证据时，声明共享证据与奖励归属。

## 8. 任务面板、详情与追踪

### 8.1 目录只突出一个行动状态

卡片的主状态由当前 Binding 决定：尚未发现、待调查、调查中、调查完成。没有额外目标的发现型条目，已满足时显示“已收录”。首次成果只显示短印记，不再并排放“研究 2/5”和“本轮 1/3”。

显示数量使用“已完成几项要求”或单个主 Objective 的准确进度，不把不同单位拼成总量。阶段顶部只显示真正的完成门槛。

收藏是 Entry 的浏览偏好；追踪是 Quest/run/phase/binding 的当前行动。收藏立刻更新书签，不立即搬动卡片；自然列表刷新时才排序。当前目录有收藏时自动显示“收藏”分类，取消最后一项后移除并回到正常分类。

### 8.2 保留次级详情，减少堆叠

详情继续半透明、跟随主题色并有打开/关闭动画。采用紧凑身份头部、“调查 / 档案”两种内容视图与限高奖励条带，避免三组目标和所有奖励堆成一个长滚动页。主面板的调查/章节奖励切换与详情的本次/首次奖励切换各自负责对应层级，不重复展示同一组报酬。

- 调查视图：只列当前 Binding 的要求、来源、是否消耗和提交按钮。有当前未完成调查时默认进入此视图。
- 档案视图：基础资料、已解锁图文、相关物品和成果来源。无当前行动时默认进入此视图。
- 奖励条带：切换本次报酬与首次档案奖励；红点表示真正可领取，不用额外长页重复列目标。采用一行概要，多组奖励同条带分页或局部滚动，不能随奖项数量不断增高挤占正文。当前无奖励时隐藏条带。

已锁资料提供准确的获准解锁说明；没有可取得来源时编辑器报告错误。点击“前往调查”只切换到真实关联任务，不凭空接取不可接任务。

面板高度随视口可用空间伸展，继续使用任务面板的 2.5 基准和用户已保存字号，保留舒适字号与拖动滚动条的独立通道，不通过统一缩小其他界面字号挤出空间。关闭动画期间固定布局快照，只改变统一 alpha / transform；文本、物品、头像、输入框一起淡出。奖励与记录更新按 revision 刷新数据，不重置表现状态。

### 8.3 点击与模态规则

条目名称或空白打开详情，物品图标执行 JEI，书签收藏，状态区追踪，奖励按钮领取；命中区不抢占彼此操作。所有有效物品都遵循同一规则，包括目标物品、显式 iconItem、相关物品和获准奖励物品；Tooltip 复用奖励栏。生物头像和纯纹理不接物品 JEI，也不抢占打开档案的点击。

状态区悬停 0.2 秒后动画切换成追踪文案并高亮；**点击从进入命中区起就有效**，0.2 秒不是点击锁。已完成条目显示明确完成状态，不留下看似失效的按钮。

占位条目可以在作者提供公开线索时追踪匿名线索；服务端只下发线索投影，不泄露隐藏实体、贴图或奖励。完全隐藏条目不提供追踪入口。

详情及关闭动画期间阻断底层 hover/click/scroll；点外部空白和 Esc 关闭。图片放大在详情之上独占输入，Esc 按层返回。真正关闭再打开任务面板清空搜索；从 JEI 返回保持当前搜索和滚动。

### 8.4 追踪器与通知

追踪器显示二维头像或物品图标、调查名称、最多两项未完成要求和简短阶段计数。档案成果是完成反馈，不成为另一组常驻目标。

条目完成后短暂确认，再转到当前阶段下一项。QUOTA 达标或需要回报时短暂提示并淡出；待领红点留在面板，不永久占视野。已满足的牛/骨头收录条目不需要继续追踪；想追踪行动就配置具体挤奶、制作或提交调查。

追踪身份随存档恢复；登录、资源重载时由追踪器自行准备头像，不能依赖先打开目录。原版使用现有二维头像适配；模组生物复用已注册纹理/UV规则，无规则留空，不回退实体模型。

通知统一左侧，合并同一事件的发现、成果与阶段完成消息，优先表达最有用的完成结果；不显示阶段加入，不恢复右上角，不为领取奖励弹 Toast。

## 9. 生命周期、重置、多人和热重载

| 场景 | 本轮目标 | 永久发现 / 成果 | 欠奖 |
| --- | --- | --- | --- |
| 正常关闭界面或下线 | 保存 | 保存 | 保存 |
| 放弃或失败 | 本轮终止，未达成目标不带到新轮 | 已取得事实保留 | 已合法解锁的欠奖保留 |
| 正常重复接取 | 新 run，从该轮阶段起算 | 保留，不重复发首次奖 | 旧 run 单独领取 |
| 管理员单任务 reset | 清该任务本轮、完成/失败、档案与欠奖 | 清关联 Entry 的发现、成果、资料权限和首次奖励凭证 | 旧资格撤销 |
| 管理员 resetall | 全部清零，下一次接取为全新轮 | 全部清零，阻止旧背包和旧迁移恢复 | 全部撤销 |

单任务 reset 后重新 give，记录型进度与本轮累计必须为零，不再提议保留关联永久成果。实时持有准备条件按第 6 节的显式库存规则处理，不能伪装成旧进度恢复；新 Demo 不依赖这种条件自动完成调查。共享 Entry 的知识清零会影响其他手册中的同一对象；其他任务独立行动与完成锁存不撤销，不相关 Entry 不受影响。服务端同步撤回资料与奖励权限。

共享 Entry 重置时撤销该 Entry 旧世代的成果和首次奖资格，包括别的手册显示的同一永久奖欠债；其他任务独立的本轮报酬保持不变。其他任务旧 Binding 的完成锁存不触发重新授予，只有新世代的有效新完成事件才可取得成果。

resetall 需要保留明确的重置世代或抑制导入事实，不能只清掉所有防回填标记。真实新事件仍可重新发现；管理员 reset 不撤回既有背包物品。正常登录库存导入只建立获准发现，不制造本轮行动或成果。

默认个人记录、个人任务、个人奖励。现有 KILL 由玩家伤害来源判定，没有自动助攻或队伍共享。若拓展协作，必须显式定义贡献、距离、队伍变更和奖励所有者；不把多人在线误写成共享调查。

当前 run 的目标、候选和规则版本固定。热重载修改数值不回退成果或已领凭证，也不静默改变旧 run 的结算；新 run 使用新定义。解锁的欠奖需保存可兑现的服务端版本或载荷快照，不能因奖励定义被改名、删除或替换就丢失或变额。

## 10. 新 Demo 的完整体验

| 条目 | 建议的发现 | 唯一调查 | 永久成果与奖励 |
| --- | --- | --- | --- |
| 僵尸 | 首次击败；公开基础资料 | 击败 3 只＋提交腐肉 2 | 解剖记录；首次铁粒×3，本次绿宝石×1；删除永久击败 5 |
| 骷髅 | 首次击败 | 本轮击败 2 只 | 战斗记录；不再累计另一份击败数，也不把击杀命名为远程行为观察 |
| 蜘蛛 | 隐藏占位，给明确公开线索 | 初版使用真实击败/样本目标，不伪称自动识别攀爬 | 对应调查笔记；已有二维蜘蛛头像可复用 |
| 牛 | 首次互动 | 入门收录可直接认可发现；需要深入玩法时明确成功挤奶或交付牛奶 | 前者不自动产生深入成果；后者取得牧场资料 |
| 骨头 | 首次获得 | 入门收录可用旧发现；行动调查用制作骨粉或提交骨头 | 对应使用记录，不设永久重复收集 |
| 煤炭 | 首次获得 | 提交 5 份煤炭样本，或明确支持的燃料实验 | `fuel_samples` 迁为成果事实，删除永久 COLLECT 5 |
| 原木 Tag | 获得任意原木 | 提交任意原木共 8 个 | 木材样本；数量与种类明确分开 |
| 铁锭 | 首次获得 | 明写“用铁粒合成铁锭”；若接受冶炼，接入真实冶炼事件 | 制备记录；重复报酬避免可逆配方免费循环 |

僵尸场景：新存档能看基础介绍，但标“尚未发现”。接取后首次击败：记录发现、本次击败变成 1/3；没有另一个研究 1/5。击败达到 3/3、提交腐肉达到 2/2：调查完成、解剖资料公开、铁粒与绿宝石可领。再次接可重复委托：仍有解剖资料，铁粒显示已领，本次要求重新计数，只可获得本轮报酬。

没有解剖记录的玩家只能通过标准调查或明确登记的等价来源首次取得它。旧重复 Demo 中的“击败 2 只僵尸”不是“击败 3 只＋提交腐肉 2”的自动等价来源；它只完成自己的委托。

未接任务先击败僵尸：保留已发现，后续调查行动从零起算；界面明确“本轮”。单任务 reset 后 give：发现和调查都回到零，旧解剖资料撤回，允许真实新行为重新取得首次奖。

三个范例的职责也应分开：

1. 入门手册：一次性 ALL，演示公开基础资料、发现和一份完整调查，少量首次成果奖励。
2. 重复委托：QUOTA，候选都是实际本轮行为或消耗提交，不用全已发现候选组成“新发现”任务。
3. 联合调查：准备 → 生物 / 材料并行 → 当前 run 汇合回报，演示独立条目追踪，不使用长期合流 flags。

## 11. 配置和存档迁移

### 11.1 配置易用性

建议编辑流程：定义 Entry 与发现方式 → 给真实 Phase 添加调查目标 → 用 Binding 引用目标 → 可选“完成后记录某成果” → 配本次报酬与成果首次奖励 → 预览各玩家状态。

Outcome 不出现“添加研究目标”按钮。成果来源显示真实调查路径；缺失来源、空必需条件、成果循环、重复奖励 ID、配额不足、隐藏目标无公开线索、重复经济奖励仅依赖永久事实等配置给出明确诊断。

示意配置，**不是现有可调用 API**：

```text
Entry zombie
  discover: 首次击败
  outcome anatomy: 解剖记录，解锁笔记，首次奖励铁粒×3

Phase survey
  objective zombie_kill: 击败僵尸×3
  objective flesh_sample: 实际提交腐肉×2
  binding zombie_investigation
    objectives: [zombie_kill, flesh_sample]
    recordOutcome: anatomy
    runReward: 绿宝石×1
```

不能把目标复制到成果定义。现有 `.research()` / `.researchStep()` / `.researchReward()` 与 Entry 级 `.bindingReward()` 需要有版本化转换和诊断，不能只改方法名就宣称重复玩法消失。

### 11.2 保守迁移

- 保留 Entry、Objective、Binding、图文和奖励的稳定身份与既有已发现事实。
- 已完成旧研究，通过作者显式映射转换成对应成果；已领取 `researchReward` 转换为同一首次成果的已领凭证，防止重复发铁粒。合法已解锁未领取的旧研究奖励保留原版本载荷与资格，转为可领取欠债。
- 未完成旧研究如 2/5，不直接改成新 Binding 2/3，也不因新门槛较低就发奖。保留迁移备份，但不伪造本轮行为。
- 正在进行的旧任务推荐按冻结旧规则结算；下一轮使用新玩法。尚依赖 researchStep 的旧 run 使用隔离的版本化兼容执行器，直到结算结束；不能只冻结 ID 后删除监听或交给新执行器解释。兼容计数只服务旧 run，不成为新玩法的第二套研究目标。确需立即重开时，明确处理进度、欠奖和玩家提示，不静默替换。
- 旧 Entry 级 `bindingReward` 逐一映射到实际 Binding；归档欠奖继续可领，不能删除旧定义后让凭证成为无效记录。
- 旧 `.researched()` 不能直接改成“任意成果存在”；需要显式指定认可的成果，空成果条目不被算作深入调查完成。
- 单任务 reset 的旧防回填标记继续生效；迁移不能恢复管理员已清掉的知识和奖励。
- AUTO 奖励不能因迁移、重登或刷新再次执行。旧记录中部分发放失败但已有领取凭证的情况按显式恢复策略处理，不无条件重发全部奖励。

## 12. 性能、验证与实施批次

新玩法不再建立独立永久 Research 监听；兼容旧 run 的版本化执行器在其结算后退出。常驻新服务只处理未完成的发现规则，当前调查复用任务索引。按事件查候选，不每 tick 扫所有玩家的所有条目。不为了“自动发现生物”增加默认附近实体扫描。

库存核对只对有相关需求的玩家和物品类别进行。客户端按定义版本、记录 revision 和 run revision 缓存目录/资料/奖励投影，只渲染视口可见卡片；头像共用缓存，资源重载时失效，不每帧生成图片或打开文件。

这些能减少重复计算，但不能据此宣称已经达到生产性能水平。验收应分别测服务器多人事件负载和客户端多条目渲染，记录硬件、条目量、同时活跃任务量、P95/P99 tick 时间、同步字节与帧时间，不能用平均 FPS 或构建成功代替负载证据。

建议分批实现、分批提交，两端同步：

1. **玩法与存档**：Outcome 事实、唯一 Binding 调查、标准来源校验、旧规则版本与迁移。
2. **奖励与生命周期**：奖励归属、预告权限、欠奖、放弃重接、resetall、当前 run 并行汇合。
3. **事件与防刷**：明确持有/来源/提交语义、一次事件批量结算、Tag 候选与经济循环诊断。
4. **面板与追踪**：移除独立研究进度、档案/调查切换、奖励条带、即时追踪点击、线索投影、动画稳定。
5. **范例与验收**：更新三种 Demo、编辑器、中英翻译、旧存档案例和两端真实客户端/服务端验证。

最低验收矩阵：

| 场景 | 必须满足 |
| --- | --- |
| 新存档未接触僵尸 | 公开基础资料可看；发现为零；调查未伪完成 |
| 首次有效击败 | 发现一次，当前目标只推进一次，不出现第二份研究计数 |
| 简单发现 Binding | 不授予解剖成果或高级奖励 |
| 两个等价调查同时完成 | 成果与首次奖励一次；各自真实本轮报酬分别处理 |
| 物品丢弃/重捡、容器往返、互扔 | 持有/提交/受支持来源目标不累计虚假新样本；旧 COLLECT 边界明确 |
| 可逆合成、反复右键、放弃重接 | 不绕过真实成本、成功条件或履约/冷却 |
