# 通用内容能力 API 与迁移契约

日期：2026-11-07。代码使用 Java 注册。本文描述当前源码，验收结果另见 DuelQuest 执行矩阵。公共调用均以生产 JAR 为依赖，禁止兄弟项目引用另一个工程的 classes 输出。

## 线程、授权与重载

- `collections` 是服务端主线程纯查询：不接任务、不记录到访、不奖励物品。快照不可变，调用间不缓存授权；需缓存地址而非授权结果。隐藏分类和未披露变体不进入结果。公开但黯淡的条目可查询，与已发现/已研究/可获取分别表达。
- 客户端内容同步按本次选定的运行实例投影。一次同步内，每个任务的阶段进度只计算一次并供条目授权复用；该临时结果不跨同步、不跨玩家保存，下一次记录变更、重置或重载仍重新检查。分类条件也不会被长期授权缓存绕过。
- Definition 仍取运行实例冻结玩法；只有同 atlas、同完整条目集合的展示变更可采用当前展示。归档按精确 runId 查询，当前活动实例优先于同 run 的旧归档。
- migration 注册发生在 common setup。版本标签仅作廉价筛选，完整来源哈希才授权。编辑发生在独立副本；预览与提交之间如有进度变化，提交拒绝。备份和回执随同一 ArcQ 玩家文件保存；整批 reconcile 异常恢复整个修改前快照。`Scope.PAUSED` 用于普通暂停任务，图鉴暂停态依旧由归档权威版本管理。
- 迁移不发奖励、不重新接取、不执行 enter；完成/失败总状态优先于旧 ACTIVE 快照。恢复拒绝覆盖迁移后已发生的玩法变化。容量用尽显式失败，不静默删除备份。
- `structures` 只在服务端线程调用，轮询续租 100 tick。每 tick 最多扫描 16 个候选、调度部分软预算 2 ms、探测间隔 5 tick、全局一个在途区块生成；这不是底层生成的硬耗时承诺。每人最多 8 个搜索、全局 128 个。取消/离线释放需求，已交给原版的生成任务不伪称可撤回。负缓存 600 tick，跨世界重启不保留瞬态共享缓存。第三方 placement 通过注册适配器补候选。
- 仍有有效需求时，已核实缓存可以跨维度读取，供异维度目的地标点展示；新的结构搜索只在玩家当前维度启动。明确取消的请求即使有缓存也返回 `CANCELLED`，不会借读缓存重开已取消的追踪。
- observation 是观察和信息公开，不是付款/研究。结构只读已加载的 start/reference pieces，不为观察加载远方区块。Curios 通道可以观察，但不自动赋予扣除穿戴物品的权限。PRESERVE 与 REVISIT 公开策略各自处理管理员重置。
- `Disclosure.historicalFlags` 可声明旧内容研究回执，只公开信息，不设置维度到访旗标。可信物品记录完成后，核心立即统一公开同档信息；新取得证据可重开已重置分类，旧库存/旧旗标只读重放不能撤销重置。维度事件只观察事件的 from/to，普通 reconcile 才读取玩家当前位置。
- 获取方案从真实当前商店定义投影，所有费用完整保留；缺失商品、无匹配和方案超限返回不同状态，均不解释成免费。默认过滤隐藏商品。`PUBLIC_CATALOGUE` 只能由可信内容服务端显式选择，适用于已公开的全装备册；客户端不能自行选择绕过隐藏信息。索引以 immutable shop 对象为键，替换定义后自然重建，动态费用仍每次实时评估。

## 费用和持久化边界

`CostPlan` 对物品/标签/NBT 条件做联合分配，不让同一堆栈满足两个重叠要求。报价不预扣；付款重新检查资源和原外部存储身份，报价只允许消费一次。主副手和已注册外部存储可扣，鼠标游标只观察不扣。普通付款全扣或全不扣；同一调用内失败逆序回滚。调用方必须在同步事务内消费/回滚回执，不能拿回滚快照跨 tick 覆盖后来取得的物品。

RecoverableSettlement 只协调实现协议的参与者。调用方必须先持久化精确计划、owner、receipt、payload，再 commit。每个参与者必须原子保存其自身效果与回执；重试先查回执，不能把当前选择的网络当成原网络。部分参与者不可用时保留业务 journal，之后重放；cancel 尽力逆序补偿并保留所有异常。finish 只能在业务已持久提交后清理。任意 Lambda、传送、世界方块变化不自动具有跨文件原子性。DQ 保留施工 journal 与世界恢复状态机，通过此协议接外部存储。

内置 `arc_quest:durable_storage` 参与者在服务首次访问前完成注册，作者不得覆盖；重复类型注册明确拒绝。它以持久计划中的 Identity 恢复原存储，不读取玩家现选网络替代付款来源。

查询已付款回执、取消和清理可使用原网络的恢复视图；新的扣款要求原付款人在线，并通过其当前授权视图再次匹配计划 Identity。没有该身份的当前授权来源时明确拒绝，不会从另一个主网络扣款；已确认提交的回执重放不会再次发起新扣款。

RewardClaimService 将 `ArcQuestRewardClaims` 存在原版玩家持久数据，使待领回执与真实背包随同一份 playerdata 保存。权益与发货分离：entitle 不向背包插物品；claim/claimAll 才尝试发货，满包保留待领；ESC 无网络领取动作。Key 必须显式选择角色生涯 LIFETIME 或任务运行 RUN 范围。正常任务发奖可以显式 entitle 后 claim；公共无主库存不得自动给下一访客。缺失注册物品在整个批次发货前拒绝，不得先交一部分再遗失回执。此保证不包括文件系统损坏或第三方绕开原版玩家保存的情况。

`pendingItems(player, namespace)` 仅在服务端线程返回待领物品的脱离副本，不领取、不更改权益；列表不可变，修改其中堆栈也不会修改存档。内容侧计算补发缺口时，应同时统计背包与此查询的待领物品，不能因为旧包裹 NBT 已被迁走而再次补发。遇到已移除物品仍明确拒绝解析并保留回执。

暂停 run 的普通接取入口同样拒绝重新接取；应调用 `lifecycle().resume`。这项保护覆盖普通任务和图鉴，保留原 run 与进度。终态优先，因此可重复任务不会被旧暂停标记永久阻止。

普通暂停任务的迁移结果、暂停原因和迁移前后备份在同一个 `RuntimeManagement` 副本内合并后写回；不能先更新暂停快照，再用旧管理快照覆盖。预览过期时拒绝提交，也不写入“已迁移”回执。

### 服务端调用示例

```java
var plan = new CostPlan(List.of(
        CostPlan.Requirement.item("base", Items.IRON_INGOT, 4),
        CostPlan.Requirement.item("extra", Items.IRON_INGOT, 2)));
var quote = plan.quote(player); // 联合分配，五个铁锭不会被两行重复计数。
if (quote.affordable()) {
    var payment = quote.pay(player); // 同步业务失败时调用 payment.rollback()。
}

var gift = RewardClaimService.Key.lifetime("example:story", "chapter_one_food");
ArcQuestAPI.claims().entitle(player, gift, List.of(new ItemStack(Items.BREAD, 2)));
// 只在当前明确的赠礼或领取动作内调用；不要放在每次查询或关闭界面时。
ArcQuestAPI.claims().claim(player, gift);
```

完整生产示例分别参见 DuelQuest 的 `CodexLayoutMigration`、`CodexObservationPolicies`、`AndreCatalogueDetailProvider`、`StoryActions`、`ObservatoryConstruction`、`WorkstationTutorialService`、`AndreAtlasTooltip`、`StoryRevision` 与 `StoryCameraController`。这些是实际调用点，不是第二套实现。

## 教学与表现

- TutorialSessions 负责菜单引用、containerId、随机 token、revision、旧请求拒绝、每四 tick 差异刷新与关闭/登出清理。同一玩家一次只有一个菜单会话。
- `tutorials().progress(player, definitionId, course)` 管理暂停、复习与已读偏好，存于原版玩家数据 `ArcQuestTutorialProgress`，与任务进度分离；`importLegacy` 只导入一次。修改偏好立即保存。请求先通过菜单身份与 revision 检查，之后才可改偏好。内容可按既有规则在下次打开未完成课程时自动展开，核心不擅自推进课程。
- Definition 决定课程资格、原生步骤和真实进度；TutorialStep 是不可变显示快照，含槽位、控件、虚拟堆栈及完成表现。core 负责完整 Component/NBT 差异签名。
- Evidence 只允许可信服务端适配器提交，按来源和会话内单调 operationId 去重；普通点击、Shift 和其它合法取出均应由原生真实操作事件统一产生。客户端只能请求暂停、恢复、复习和非经济确认，不能自报加工成功。
- WorkstationTutorialOverlay 提供通用卡片、槽位/虚拟物品、输入、Tooltip 避让和 JEI 排除。第三方控件通过 registerControlAdapter 提供几何；不向核心引入神化/DuelCraft 依赖。教学关闭不会禁止原设施加工。
- AtlasRenderContext 含实际像素密度、可读字号、主题、透明度和 journal 逻辑坐标中的裁剪/Tooltip 避让几何。装饰图标与条目真实元素分离；stack 的 SNBT 使用统一大小/深度限制，resolveStack 总返回副本，绝不作为条目授权或实物领取凭据。
- DialoguePageSequence 保留第一页旧入口/入场音效和末页原选择、条件、动作；中间页只有继续。重复阅读不新增经济回执；具体赠食、拒绝等选择仍是内容声明。
- FocusCoordinator 不写玩家坐标、旋转或游戏权威状态。优先级高者获得焦点，同级较新者优先；挂起期间播放时钟不前进。Suspension 可嵌套且 close 幂等，所有者替换/断线/死亡/跨维度均明确结束。生命周期回调失败仍清理句柄。具体镜头路径、碰撞和 EF 相机兼容在内容适配器中。

死亡重生的 `PlayerEvent.Clone` 显式深复制待领回执与教程偏好，保留已交付记录、未交付内容和一次性旧数据导入标记，且关闭旧菜单会话；新旧玩家对象不会共享可变 NBT。维度切换和正常重新登录沿用同一份原版玩家持久数据。

## 兼容与发布

本批是 ArcQ/DQ 配套更新；菜单教学改用 `arc_quest:tutorial` 通道，不保留两条并行生产通道。旧玩家课程和待领内容在 DQ 兼容层导入，原课程进度不重置；旧定位缓存只导入一次。必须同步生产与 sources JAR，不能只更新源码便将旧客户端结果当成新版本验收。
